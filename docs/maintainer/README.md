# 长缨辅学 · 产品全景与维护指南

> **写给谁**：接管长缨日常开发维护的产品维护者（教师助理）。你不需要会写代码，代码由 AI 写。你负责弄清需求、做取舍、验收、决定上线。业务负责人定期推进业务、审核产品方向。
>
> **怎么用**：第一周把第 0～6 节读一遍。之后遇到问题，按目录回来查。也可以直接问 AI：“按维护指南，这个需求会影响哪些模块？”
>
> **谁来更新**：模块有变化时，AI 会在同一次改动里同步更新本文件。你在工作中学到的东西，也可以让 AI 补进来。
>
> 版本：2026-10-31

## 0. 一分钟版

- **长缨是什么**：给小学培训机构和学校用的教学系统。老师备课、上课、布置练习；学生作答；系统记录每个孩子的长期学习档案；家长看到孩子的学情反馈。
- **你每天做三件事**：
  1. 把老师的反馈整理成清楚的需求，发给 AI；
  2. AI 改完后，在真实网站上验收；
  3. 你说“合并”，改动才会上线。
- **遇到红色事项先停一下**（见第 7 节）：删数据、新建数据表、登录权限、付款、密钥、服务器设置。
- **一个原则**：长缨各模块是连在一起的。改一个地方之前，先问“它还会影响哪里”（见第 6 节）。

## 1. 角色与分工

| 角色 | 负责什么 |
|---|---|
| **你（产品维护者）** | 收集和判断需求、决定做不做、做到什么程度；验收；决定上线（说“合并”）；记录待办和决策 |
| **业务负责人** | 定期推进业务、审核产品方向；你把重大取舍和每周进展报告给他 |
| **AI 工程助手**（Claude、DeepSeek、Freeman 等） | 写代码、写测试、检查上线；每次回复都说明影响范围、风险、建议和验收步骤 |

你接手的是业务负责人原有的仓库和账号，下面这些账号操作也由你负责：

- GitHub 付款、额度和设置；
- Render 服务器设置；
- 各种 API 密钥。

这些都属于红色事项（见第 7 节）。AI 不会替你点按钮，也不会碰密钥本身，它会写出一步一步的操作说明，你照着在网页上做。**密钥只在服务商网站和 Render 设置页之间复制粘贴，不要发给 AI，也不要写进任何文档。**

## 2. 产品原则（判断一个需求前，先对照这七条）

1. **只做小学教学。** 机构教学、学校教学、学生档案、家校联系、升年级衔接都在范围内。便利店、健身、市场运营这类无关业务不做。
2. **一个学生只有一份长期档案。** 换班、换老师、上周末课、做模拟卷，记录都进同一个学生名下，不复制学生。
3. **AI 只写草稿，老师审核后才生效。** AI 出的题、写的教案、写的学情报告，都要老师确认，才会到学生和家长那里。
4. **分数由系统算，AI 不判对错。** 照片预批中 AI 只抄录题目与手写答案，由程序核对可验算的数值或代数式；老师核验保存后才成为正式批改。掌握程度只看学生**第一次作答**；题太少时显示“证据不足”，不硬下结论。
5. **不排名，只和自己比。** 家长只能看到自己孩子，看不到别的孩子。
6. **旧设备也要能用。** 学生常用旧 iPad（iOS 12），新功能都要在旧设备上能打开。
7. **不编数据。** 系统没有的数据（比如学校课表），界面上不虚构。

需求和原则冲突时，AI 会指出来，由你决定：放弃这个需求、调整做法，或者报给业务负责人。

## 3. 谁在用，从哪里进

网址：`https://primary-school-quiz-v7.onrender.com/v1`，登录后按身份进入不同首页。

| 身份 | 首页 | 常用功能 |
|---|---|---|
| **老师** | 工作台（当前教学） | 周末课、晚托、班级、作业、知识地图、应试专项、学生档案、往期教学、升年级衔接 |
| **学生** | 学习首页（同步课堂） | 当前课堂、课堂练习、我的知识地图、限时模拟卷、作业、自主练习 |
| **家长** | 孩子学情 | 周末课学情反馈、考试提分报告、作业和成绩 |
| **管理员** | 管理功能 | 账号、学校设置 |

- **“全部功能”（`/v1/tool`）**：列出所有功能。有些老功能点进去仍会打开旧界面，这是正常的。
- **角色实操沙盒（`/v1/training`）**：用虚拟账号把老师、学生的完整流程真实操作一遍，**不会写入正式数据**。新人学习就从这里开始（见第 11 节）。

### 3.1 老师分两种场景，但不是两套权限

“老师”这个身份**同时覆盖机构教师和学校教师**，两种场景的入口不同：

| 场景 | 典型入口 | 说明 |
|---|---|---|
| **机构（晚托、周末课）** | 周末课、晚托作业助手、应试专项 | 家长把学校通知发给机构老师，老师导入系统 |
| **学校教学** | 往期教学（`/v1/teacher/history/classrooms`、`/v1/teacher/history/students`） | 学校教师自己登录使用，不经过机构 |

> **“教学周期”要注意**：接口 `/v1/teaching-cycles` 教师和管理员**可以调用**，但工作台**默认不显示这个入口**——代码只在机构模式、并且不是“正常学期”时才去请求它（`v1.py:181`）。所以不能说“学校模式就从这里进”，否则按文档会找不到。

**“学校 / 机构”是登录后的工作模式**，不是两种账号：底层账户只有一个角色（老师）和一个所属学校。切到学校模式时，工作台标题和任务清单会变，但**授权判断不读这个模式**。

> 依据：已核对的接口继续按角色、学校范围及各接口自身的数据归属规则授权，**未发现按工作模式区分授权的分支**（例：`v1_teaching_cycle.py:20` 是 `need(user,"teacher","admin")` + 按 `school_id` 过滤；`v1.py:179` 的 `isSchool` 只改标题与任务清单）。这只是对已核对接口的结论，不代表全部接口都逐条查过。

可见范围：老师只能看到本校、本人班级和学生；学生只能看到自己；家长只能看到自己孩子已发布的内容；管理员管本校账号。**没有跨校访问，也没有平台级管理员。**具体到每个接口还各有自己的数据归属规则，细节见 [`docs/V1_SCOPE.md`](../V1_SCOPE.md) 的“权限边界”。

> 早期资料里出现过“学校教师不直接操作长缨”的说法，那是不准确的，以本节为准。

## 4. 模块全景

每个模块按同一个格式写：**做什么 → 主要流程 → 和谁相连 → 现状与注意**。

### 4.1 题库与作业（所有模块的底座）

- **做什么**：存放所有题目；老师组卷、布置作业；学生作答；系统判分；错题进错题本。
- **主要流程**：导入或 AI 出题 → 老师审核 → 组卷 → 布置 → 学生作答 → 判分 → 记入档案。
- **和谁相连**：周末课、知识地图、应试专项、针对性练习用的都是这个题库；**所有作答都进同一套提交记录**，学生档案、错题本、知识地图掌握度、学情报告都从这里读。
- **注意**：
  - 改题目的格式或内容，会同时影响好几个模块（见第 6 节）。
  - 题目有题型：选择、判断、填空、计算、解决问题，以及要老师批改的开放题。
  - 普通在线作业可以保存草稿、分题提交和稍后继续；每道题首次提交后默认还能修改 3 次（合计 4 次），各题分别计数。老师只能为自己班级的指定学生按整份作业追加修改次数，并可查看逐题提交历史。
  - 部分提交显示“进行中”，分数仍以整张试卷为分母；第一次覆盖全部题目时才发一次完成积分，后续修改不重复发分。修改始终复用原来的作业提交记录，逐题版本另存历史，不能覆盖其他题的有效答案。
  - 本功能上线前已经存在的作业提交继续视为“已完成”，不会重新判断状态、重算积分或改写历史数据。拍照／视频作业仍走原流程，不在这套修改规则内。

### 4.2 学生连续档案

- **做什么**：一个学生一份长期档案，包括班级历史、作业、成绩、薄弱知识点、老师跟进、家长关联、时间线。
- **和谁相连**：所有模块的作答结果最终都汇到这里。
- **注意**：
  - 系统不会自动给出“已掌握”“能力强”这类长期结论，这些留给老师判断。
  - 学习证据分四个维度：作答表现、独立完成、保持、迁移。后三项由老师记录。

### 4.3 周末课（最常用，也最复杂）

- **调试课堂撤销**：在备课页先点“撤销调试课堂”，核对课堂名单并确认没有实际上课。仅本人没有学生作答/提示/讲题/积分/反馈的课堂可撤销（点过结束也可以，但仍须确认未实际上课）；其他老师的课堂和关联报告会阻止操作。撤销保留教案和备课习题，清除课堂计时、翻页、互动课件显示状态、班级绑定和课堂习题副本，并保存操作快照。之后可重新开课，或另点“删除教案”。恢复须由维护者依据快照核对，不提供直接撤销恢复按钮。没有电子作答不等于没上过课，实际讲授过的课堂不要按调试撤销。

- **做什么**：机构的周末课，从备课、上课到课后反馈的完整流程，共 18 次课。
- **主要流程**：
  1. **备课**（`/v1/weekend-plan`）：在进度表里每次课“导入我的教案”或让 AI 写，接着“AI 出习题”，再在“审改”里分四块处理：
     - 教案编辑：重新导入前会保存整份备课内容。在“审改”里点“恢复重新导入前的整份教案”，可取回原文、习题、原图和互动课件。结构化 JSON 整包按内容识别，即使文件扩展名丢失也走本地导入；Word/PPT/PDF 在本地提取；符合约定格式时按规则拆题，普通文档则原文保存为草稿，不调用外部 AI，也不会自动拆分习题。重新导入后又修改了内容，或课次已有课堂或学生记录时，系统会阻止恢复；
     - 习题审核：页面分开显示**例题讲解**与**随堂练习候选**，顶部先列出这节课的题数——例题几道（其中几道待审核）、可用练习几道（其中几道待审核）、互动课件是否已通过，开课前不用翻页就知道第 4 环节有没有题。例题可以**逐题审核**：核对题干、答案和配图后点“核对通过”，也可以“撤回审核”或“全部标记为已通过”；例题内容一改，状态自动变回“已修改，待重新审核”；上线前就存在的旧课显示“历史·已通过”，不会被要求重审。例题审核和互动课件审核分开记录，一项通过不代表另一项通过。第 3 环节的例题只用于教师讲解，不会自动发给学生；只有审核通过的随堂练习才会进入第 4 环节。与本课例题或已通过题目重复的候选题不能通过，应替换为同考点的新题；**已经通过的旧重复题**会标出“与例X重复”，并多一个“撤回通过（课堂记录保留）”按钮，撤回后题目还在备课里，已有课堂记录不动；每道文字题在这里标一个**考点**（系统按题目小标题先填好，可一键“采用全部考点建议”，也可以从本课训练目标里选），标一次这节课的所有班级通用；课后才做的题勾“**课后题**”；
     - 原文核对：导入时的原文，只作存档；
     - 互动课件：给例题与已通过的随堂练习逐题配分步讲解和图示。已有教案可在此选择预制课件 JSON，先预检再导入待审核草稿；系统核对原题文字，不调用外部 AI，也不改已有教案或习题。默认不覆盖已有页；需要替换时勾选“替换对应页并保留上一版”，确认后生成新草稿，已审核版本保留至新草稿通过；教师逐步核对图示和答案后再审核。第4环节按题干及选择题选项匹配，课堂公布对应题答案后才展示课件；题目不唯一时暂停展示。
     - 单独导入随堂练习：不用重导教案，在习题审核里展开“单独导入随堂练习（不动教案和例题）”，粘贴题目文字或上传文件。识别结果只进**随堂练习候选**（待审核），页面会显示识别到几道选择题、几道文字题、几道因与例题重复被丢掉、几张配图；识别不出题目会直接报错，不写任何数据，教案和例题不受影响。
     - 混合资料导入分组与用途切换（PR #1084）：同时包含例题和练习的资料导入时，系统按标题、题号提出分组建议，老师可一键确认或逐题切换「例题讲解／随堂练习」；缺图题会提醒补图或确认无图。
     - 开课后再审核与手动同步（PR #1084）：选择题上课时实时取；文字题在开课时复制进当前课堂，之后新通过的文字题可在控制页点「同步新审核练习」手动带入当前课堂（不自动覆盖已开课堂进度）。
  2. **开课**：要有教案，并且至少 1 道**可用随堂练习**审核通过（0 道可用随堂练习时禁止开课，PR #1084；灰色按钮旁边会写出还差什么）。
  3. **上课**（控制页 `/v1/weekend?s=…`）：按 7 个环节推进——到课与热身、知识点介绍、例题讲解、随堂练习、练习复盘、课堂互动、布置课后。
     - 互动课件按本次课堂和页码保存讲解进度；返回已讲过的页可以继续，新的课堂从初始状态开始。切页后，旧页迟到的操作会被拒绝，请在当前页重新操作。
     - **大屏**（`/v1/weekend-board`）：自动排版，知识点卡和例题卡分开；讲解环节的答案默认遮住；随堂练习的答案要老师逐题公布；第 4 环节没有可用练习时，大屏会直接写出“本节课第4环节还没有可用的随堂练习”并指向习题审核。
     - **学生平板**（`/v1/weekend-practice`）：作答，可以用阶梯提示。
     - **强带弱、进步分、团队分**：系统建议请谁讲题，课后结算积分。
  4. **课后**：
     - 先在上课页“学生作答与批改”批完照片题。同一道题全班答案排在一起，可以先点“本题待批全部标为正确”，再把做错的几份改掉；
     - 打开“课后总结与家长反馈”（`/v1/weekend-report`）。还没标考点的文字题，可以在“逐题统计”里直接标；
     - 点“为全班生成草稿”，一次生成每个孩子的草稿（不发布）。老师逐份核对修改后发布，也可以“发布全部草稿”（会列出名单再确认）。也能下载 Word；
     - 家长看到的每节课最上面有“**一眼看懂**”：掌握得好的考点（绿）、需要加强的考点（橙）、回家做的一件事、和孩子自己上次比（不和别的孩子比）；
     - 薄弱考点如果对得上知识地图上的知识点，或者孩子晚托时请 AI 讲过、还没巩固，草稿的“课后任务”里会自动加一句提示。
  5. **纸质备用**：上课页“纸质备用与课后补录”可以下载教师版、学生版 Word 打印；断网时纸上作答，课后再补录。
- **和谁相连**：题库、学生档案、家长端、知识地图（学生练习页顶部有“课前诊断／课后补测”入口）。
- **注意**：
  - **统计口径**：标了“课后题”、还没交的题，记为“课后题未交”，不算本节应做题，也不算“未提交”；交了以后照常统计。
  - **考点只读老师确认过的**：系统建议的考点要老师保存后才进报告。没标的题，报告里写题目任务，不写考点。
  - **教案和习题是分开存的。** 删掉习题，大屏、学生端、打印 Word 会自动跟着变；教案文字不会变。
  - **系统不保存导入的原文件**，只保存从中读出的文字。原文件的备份在老师自己的电脑里。
  - 大屏排版按每行的开头词识别，例如“考点一：”“示例：例题1 |”“易错：”“参考答案：”。教案写法越规整，大屏越清楚。

#### 照片／文字答案预批

- 学生提交后，系统在后台生成**仅本课老师可见**的预批建议，原答案先保持“待批”。已有待批答案可在老师打开批改页时补充生成，也可点“生成／重试预批”。
- 点击后，本份答案旁立即显示排队或识别进度，完成后自动更新建议，不用反复点击或刷新全班；老师未保存的评语与批改选择会保留。已有答案补充识别每次最多并行两份，其余排队。超时、服务未开启或用量受限会在原位置说明，仍可手工批改。
- 识别服务只抄录照片中的印刷题目和手写答案，不接收参考答案、不决定对错；程序检查小题对应、识别把握和答案空数，再核对数值、分数、百分数及简单多项式的等价性。题目不对应、字迹模糊、单位换算、复杂过程或文字题等无法可靠核对时提示人工核验，不能一键采用。
- 老师逐项查看原图、识别内容、参考答案和核对依据。识别错误可直接修改，点“已核对／修正识别内容，重新预批”；此时仍不算正式批改。全部核对后点“我已逐项核验，采用预批并保存”，也可直接使用原来的手工批改按钮。
- 学生重交、老师已批改、题目或参考答案更新后，旧预批不能直接采用。学生、家长看不到识别内容、预批建议和参考答案，仍按原有公布规则看正式反馈。
- 识别沿用学校现有 AI 授权、识别配置和用量限制。未开启、超时或失败时照常保存答案，老师可重试或手工批改；不要把密钥发给工程助手。
- 预批失败会分别提示识别授权失败、计费限制、服务商限流、接口或模型未找到、网络不通、超时、返回内容为空等类别。具体上游状态码和固定错误类别也写入运行日志，供工程排查；不记录密钥、照片、学生答案或服务商原始报错。状态码只能指明排查方向，不能代替管理员核实服务商设置和账户状态。
- 独立记录表 `weekend_written_prechecks` 保存版本化建议，不复制原图、不覆盖原始答案。首次上线会新增该表；回退应用后原答案与已确认批改保留，额外建议表可保留。上线前需维护者明确确认数据库新增表及清理分类；本功能不执行生产清理或历史回填。

### 4.4 知识地图（`/v1/knowledge-map`，学生端 `/v1/my-knowledge-map`）

- **做什么**：把一册教材整理成“单元 → 知识点 → 先学什么”，每个知识点的题分成基础、中等、提高三档。学生做诊断，就能看到自己哪里薄弱。
- **主要流程**：
  1. 老师按模板建地图（目前有人教版五年级上册数学，另有 2026 人教版三年级、六年级上册数学模板）。模板存在不等于学校已创建、配题或发布。
  2. 给每个知识点配题，三种方式：从题库挑、AI 出题、系统画图题。
  3. 把题分到三个难度档。
  4. 发布。
  5. 学生做 12 题入门诊断，以后可以点任意知识点做 3～5 题小测。
  6. 老师看全班颜色表，一键给薄弱学生布置巩固练习，并记录自己的判断，与系统结论对比一致率（目标 ≥ 80%）。
- **AI 出题的规则**：按单元选“考法”（计算类、图形类、可能性类三套）；同一批题不重复考法；数学答案按算式重新验算，算错的题直接丢掉；可能性单元只做定性比较（课标要求）。
- **掌握度怎么算**：只看第一次作答；基础题权重 1、中等 1.5、提高 2；结果低于 0.6 为薄弱，0.6～0.85 为达标，高于 0.85 为熟练；不到 3 道题显示“证据不足”。
- **跨场景学习证据（PR #1085）**：班级掌握度表提供「查看证据（N）」及节点证据摘要，按来源列示周末课、晚托求助、知识地图测验与应试专项记录（未追踪帮助/提示状态时标为“未知”），**不改变**上述掌握度计算公式。
- **注意**：
  - 学生只看得到**已发布**的地图，而且只看自己年级的。学生端看不到地图时，先查是否已发布、学生年级是否设对。
  - 目前的做法是全部知识点过完题再发布。系统本身允许先发布已学的单元。
  - 晚托作业助手讲题时也读这张地图（见 4.7）：地图没发布，晚托讲题就不会出现“这道题在你的知识地图上”。

### 4.5 应试专项（`/v1/exam-prep`，学生 `/v1/exam-paper`，家长 `/v1/exam-report`）

- **做什么**：围绕一场考试（期中、期末）提分：摸底 → 找失分点 → 专项练习 → 再测对比。
- **主要流程**：
  1. 建考试目标：日期、范围、班级。
  2. 发模拟卷：限时作答。
  3. 看每个学生的失分点（最多 3 个）。
  4. 一键布置专项练习。
  5. 发再测卷，对比前后。
  6. 生成家长提分报告：老师写评语后发布。
- **和谁相连**：题来自知识地图和题库；结果进学生档案；报告到家长端。考卷分析同时展示失分点在周末课、晚托求助与知识地图测验中的跨场景学习证据（PR #1086），仅作讲评参考，不改变分数、失分排名和专项/再测组卷规则。
- **注意**：不排名；计分是选择 2 分、判断 1 分、填空 2 分、计算 3 分、解决问题 5 分；时间到了不会强制收卷。**31 项验收单还没有验收。**

### 4.6 同步课堂／互动课堂（日常课堂）

- **做什么**：课堂上的随堂检测、请学生讲题、课堂复盘、课堂讲义。
- **注意**：讲义按版本发布，学生只看当前版本；课堂积分只在老师明确加分时才产生。

### 4.7 晚托（作业助手，`/v1/homework`）

- **做什么**：
  - 老师把学校的作业通知（拍照或文字）交给 AI 整理成作业清单，发给学生；
  - 学生勾选完成，遇到不会的题拍照求助，由 AI **引导他自己做**（见下）；
  - 老师根据学生问过的题生成巩固练习，审核后布置。
- **AI 怎么讲题（2026-10-30 起）**：目标是“学会”，不是“做完”。
  1. **从他会的讲起**：学生年级有已发布的知识地图时，系统把地图和他自己的掌握情况（已会、薄弱、未测，不含姓名）交给 AI。页面上会显示：
     - 这道题在地图上是哪个知识点；
     - 他已经会的前置知识，和还薄弱、需要先回忆的前置知识；
     - 一道他以前第一次就做对的相关题；
     - 如果班里有考试目标，再提示“在考试范围里，离考试还有几天”。
  2. **每一步先问再讲**：每一步先让学生回答一个小问题（选择或填数），答错给提示，两次不对或点“这一步不会”才给讲解。只有程序验算过的数才会拿来比对；验算不了的步骤只给他看，不提问。
  3. **答案自己算**：最后的答案要学生自己填，填对才显示“你自己做出来了”。两次不对或点“还是不会”，才显示答案。语文、英语等程序核对不了的题，先写在作业本上，再点“对答案”。
  4. **真的会了吗**：讲完给一个“去做同类题”按钮，打开知识地图上这个知识点的 3～5 题小测。小测题是老师审过的，只算第一次作答，结果进掌握度。
- **补发与处理备注**：补发的清单从学生收到时起显示三天。老师处理求助时填写的是内部备注。
- **老师能看到什么**：学生点“求助老师”后，求助详情里有 AI 的引导，还有学生自己做到了哪一步（自己算出答案，还是看了答案；答错几次）。
- **注意**：
  - 学生拍的照片只用于识别，不保存。
  - 引导里的对错只用来决定给不给提示，**不计分、不进掌握度**。掌握度只来自小测和作业里老师审过的题（原则 4）。
  - 巩固练习走普通作业流程，结果进档案。
  - 晚托提问生成的巩固练习用另一套积分：按时 +3；正确率以 60% 为中点，按 10 个百分点上下各 3 分，扣到 0 为止；不再按每题 1 学习积分重复发。
  - 生产环境已开启。讲一道题仍然只调用一次 AI，引导过程在页面上进行，不额外花钱。

#### 圆面积理解辅导（已接入，固定图文待试点老师审核）

代码已接入主线；固定图文仍待试点老师审核，真实师生验收尚未完成。

- 第一版只面向六年级圆面积求助，普通求助照常使用。题目确认前可选“圆面积刚学，先回忆基础”；生成后仍不会，可在引导完成处进入固定补救。三种帮助选择只在学生主动进入补救后出现，不增加普通求助的必选步骤。
- 固定检查最多三项：同图半径/直径、四行四列方格的面积、圆周长前置。会的可选快捷路径；不会的先看对应图示，一轮为一次图示和一道确认题，同一卡点最多两轮，仍未过就引导求助老师。学生也可随时退出或求助老师。
- 圆拼合示意明确为近似，8份/16份可切换；计算示例明确给出π取3.14。原题的π取值仍按原题，含π的不可核对写法不直接判错。单位练习仅属于这次辅导，不改全站数值判分规则，也不把数值相符认定为单位正确或概念已掌握。
- 生成前的固定检查不调用AI，只有固定类别的反馈参与原有讲题提示；生成后的补救全部使用固定图示，不再请求讲题。原有验算失败时的重试策略保持不变。
- 确认题只记在原求助的辅导JSON中，跟随求助记录原有90天保留规则；不进入正式提交表，不改首次作答、成绩或地图掌握度。老师接手能看到卡点、已用帮助和当前状态的三行摘要。旧记录无此字段时照常读取。
- 无地图、题目已删除或没有足够未做过的审核题时，不显示无效小测入口；由老师安排独立验证。看过讲解后的完成与独立小测通过是两件事。

#### 待跟进（试点）

- **入口与可见性**：老师打开晚托作业助手 `/v1/homework` → 顶部「待跟进」；学生和家长看不到这份列表。
- **它是什么**：系统挑出当天最需要老师留意的求助，每条写「原因」和「验证状态」；点建议会跳到对应学生的求助详情（参数只用于定位，能不能看仍由服务端接口决定）；点「已处理」只收起建议，**不改变求助本身的状态**，求助仍要到「求助列表」确认。
- **名额口径**：**每个班每天最多 5 条**；**同一学生当天最多 1 条**；点「已处理」或「今天先不提醒」都**不返还**名额；一个学生同时在两个班，会**同时占两个班的名额**。打开列表时系统先确认名额再显示（响应丢失也只是少发，不会多发）。周末课同桌讲题巩固未完成/未做对条目已并入同一每日每班 5 条预算（晚托求助优先，PR #1086）。
- **验证状态（六类）**：无法匹配知识点 / 尚无后续作答 / 题量不足待补充 / 已有结果尚未达标 / 后续练习达到条件（达到条件的会自动从待跟进移出）/ 无法判定（判定依赖出错，只影响该学生）。判定依据是「求助之后的后续提交」按 学校+学生+学科+知识点 统计，沿用既有门槛（默认 3 题、80% 正确），不是固定写死。
- **措辞与试点边界**：真实提交不等于独立作答，所以叫「后续练习达到条件」，最终是否掌握由老师判断。这是试点；并发与旧 iPad 未在生产实测。

### 4.8 知识点讲解卡片（`/v1/knowledge`）

- **做什么**：每个知识点一张讲解卡，AI 写草稿、老师审核；学生可以搜索，做错题时也会看到对应的卡片。

### 4.9 家长端

- **能看到**：自己孩子的周末课学情反馈、考试提分报告、作业和成绩。
- **看不到**：其他孩子、答案、老师的内部备注。
- 家长和学生是多对多关联：一个家长可以关联多个孩子，一个孩子也可以有多个家长。

### 4.10 往期教学与升年级衔接（`/v1/history`、`/v1/transition`）

- **做什么**：查往期的班级和学习记录；升年级时读取档案事实，按 8 个步骤准备衔接。
- **注意**：系统不会自动改学生年级或班级。学年、学期还没有完整的数据结构，界面上不虚构。

### 4.11 教学资源与课件模板

- **做什么**：上传教学资料，AI 出题时可以作为参考；周末课的互动课件可以存为模板，套用到其他课。

### 4.12 个人免费版（独立老师）

- **做什么**：给一个人带班的独立老师用的免费版本。开一个「个人工作台」——本质上是一间只有一位老师的工作室，其他模块全部照旧。
- **怎么开**：老师自己注册，或运营在商业控制台开，两种方式建出来的一模一样。
- **和机构版的三点不同**：
  1. **只有一个账号**。这个账号既是这间工作室的管理员，也是上课的老师；不用、也不能再建第二个教师账号（家长账号照常可建）。
  2. **加学生不用建班**。系统自动维护一份「我的学生名单（N年级）」，加学生时只填姓名、账号、年级；老师看不到「班级」这个概念，但数据里仍然是一份名单，周末课开课直接用。
  3. **AI 由老师自己填**。老师在「AI 设置」页填模型地址、模型名、Key，费用由老师自己承担；机构老师仍然只能由学校管理员统一配置。
- **永久免费**：个人工作台固定免费套餐、状态已开通、没有到期日；运营控制台的改套餐、续费、额度、暂停、正式开通五个入口都对它返回 400，不会被改成只读。
- **自助注册**：登录页有「免费注册个人工作台」，填姓名、账号、密码、工作室名即可。要过一道算术验证题，并按 IP 限流（默认每小时 5 次、每天 20 次，可用 `SIGNUP_HOUR_MAX` / `SIGNUP_DAY_MAX` 调）。环境变量 `PERSONAL_SIGNUP=0` 可整体关掉（关掉后 `/signup` 返回 404），运营开通不受影响。
- **注意**：
  - 个人工作台的教学界面用教师菜单进入（登录时返回的身份是教师），但后台账号权限仍是管理员——所以它能管自己工作室的账号，范围仅限本工作室。
  - 个人工作台按角色统计「教师人数」会算成 0，因为库里是管理员账号。
  - 机构（非个人）的一切行为不变：多老师、必须建班、AI 设置归管理员、缺班级加学生仍返回 422。
- **入口**：老师登录后进当前教学；未登录可直接访问 `/signup`。
## 5. 数据是怎么串起来的

```
              导入 / AI 出题 → 老师审核
                        │
                      题　库
      ┌─────────────────┼─────────────────┐
  周末课习题        知识地图分档       应试专项组卷
      │                 │                  │
  课堂练习/大屏     诊断/小测/巩固      模拟卷/专项/再测
      │                 │                  │
      └──────────── 学生作答（同一套提交记录） ────────────┘
                        │
        学生档案 · 错题本 · 掌握度 · 失分点
                        │
        学情报告 / 提分报告 → 老师审核 → 家长
```

记住两点：

- **题库是起点**：同一道题可能同时出现在周末课、知识地图、应试专项里。
- **所有作答汇到同一个地方**：一个学生在任何地方做过一道题，知识地图掌握度、应试失分点、学情报告都会算进去。

| 知识地图的知识点、前置关系、发布 | 晚托讲题的“已会 / 薄弱”和“去做同类题”、应试专项考试范围 | 晚托求助一道题，看知识地图卡片是否对得上 |
| AI 出题的要求 | 共有三套，互相独立：知识地图 AI 出题、周末课 AI 出习题、学生档案里的 AI 针对性练习 | 说清楚改哪一套 |
| 审核、发布规则 | 学生、家长能看到什么 | 用学生号和家长号各看一遍 |
| 大屏样式 | 只影响大屏，但每个环节内容不同 | 知识点介绍、例题讲解、随堂练习各看一页 |
| 新增数据表、删除数据 | 上线前清理脚本、备份 | 红色事项，见第 7 节 |

**规律**：改“题”和“分”的影响最广；改“显示”的影响最小。

## 7. 风险分级

| 等级 | 例子 | 怎么处理 |
|---|---|---|
| 🟢 绿色 | 页面显示、排版、文字、提示、AI 出题的要求、大屏样式 | 你直接决定，验收后说“合并” |
| 🟡 黄色 | 新功能；改算分或掌握度规则；改学生和家长能看到的内容 | 先让 AI 做影响分析，再决定；重大的取舍在周报里告诉业务负责人 |
| 🔴 红色 | 删除数据；新建数据表；登录和权限；家长关联；付款；服务器设置；密钥；上线前清理脚本 | AI 会先停下来，把后果和回退办法说清楚，你明确确认后才执行；账号上的操作，AI 给步骤，你自己在网页上做 |

另外两种情况：

- **需要人工合并的改动**：比如只改文档、或改动涉及受保护的文件。AI 会告诉你，你到 GitHub 页面上点合并。
- **AI 自己也拿不准的**：它会写“建议先问业务负责人”。

## 8. 和 AI 一起工作

### 8.1 怎么提需求（照这个格式，返工最少）

```
哪里：周末课 第2课 大屏 第3页（或：知识地图 3-1 知识点）
设备：教室电脑 / 学生 iPad / 家长手机
现象：（截图，带地址栏）选项显示成 A. A．8ab
期望：只显示一个 A
急不急：下周六上课前要
```

- 一条消息只说一件事；多件事就编号。
- 说清楚是**哪一节课、哪一页、谁在用**。
- 老师的原话可以直接贴，AI 会帮你整理。

### 8.2 AI 会怎么回你

你不用说明身份，也不用每次交代规则：只要是在长缨仓库里工作的 AI，都会自动读到这些规则（写在仓库的 `AGENTS.md` 第 9 节，`CLAUDE.md` 会引导 Claude 去读它）。

**你提需求或下指令时**，AI 的回复固定用这六个小标题，名称和顺序每次都一样：

- **① 我理解的需求**：用一句话复述。理解错了，马上纠正它。
- **② 涉及的模块**：直接涉及哪些模块，还会顺带影响哪里。
- **③ 建议**：怎么做；有几种做法时，给出推荐和各自利弊。
- **④ 风险等级**：绿、黄还是红，以及为什么。
- **⑤ 上线后怎么验收**：去哪一页、用哪个身份、看什么。
- **⑥ 产品知识**：一条和这次有关的产品知识，帮你逐步建立整体认识。

一件事分几轮完成时，AI 第一轮先给 ①～④，你确认后它再动手；做完或上线时再补上 ⑤⑥。

**你只是问个简单问题**（是不是、到哪一步了），AI 会直接回答，末尾附一行“产品知识”。

AI 漏了哪个小标题，直接说“按格式补全”就行。

### 8.3 说“合并”之后会发生什么

1. AI 先确认自动检查（CI）全部通过。检查没通过就不会上线。
2. 合并后服务器自动部署，大约 3～5 分钟。
3. AI 检查线上版本，确认网站能正常打开。
4. AI 把进展记录到 GitHub Issue #174，这是工程断点记录，你不用看懂。

### 8.4 怎么验收

- 一定要在**上线后的真实网站**上验收。效果图只作参考。
- 学生功能用学生号看，家长功能用家长号看；能用旧 iPad 的，就用旧 iPad 再看一遍。
- 按 AI 给的验收步骤逐条核对；不对就截图发回去。

### 8.5 几条纪律

- **同一块内容，同一时间只让一个 AI 改。** 比如 DeepSeek 正在改知识地图页面，就不要同时让 Claude 也改它，否则会互相覆盖。
- **一件事验收完，再开下一件。**
- **不要把密码、密钥发给 AI。** AI 也不会把它们写进任何地方。

### 8.6 常见情况怎么办

| 情况 | 怎么办 |
|---|---|
| AI 说“自动检查没跑起来”，原因是付款或额度 | 到 GitHub 的 Settings → Billing and plans 更新付款方式或调高 Actions 月度上限，再让 AI 重跑 |
| 网站打不开 | 告诉 AI，它会先查线上版本和健康检查，必要时退回上一版 |
| 老师说“数据不对” | 截图，并说明是哪个学生、哪节课；**不要自己去改数据** |
| 不确定该不该做 | 问 AI：“按产品原则和影响表，这个该不该做？” |

**关于实操沙盒**（`/v1/training`）：

- 它是临时虚拟环境，账号和数据都是假的，8 小时后自动清除，随便点不会影响任何人。

## 12. 术语表

| 词 | 意思 |
|---|---|
| PR | 一次改动的申请单。AI 改完代码会开一个 PR，附说明 |
| 合并 | 同意这次改动，合进正式版本；合并后会自动上线 |
| CI / 自动检查 | 每次改动自动跑的测试。不通过就不能合并 |
| 上线 / 部署 | 新版本放到服务器（Render）上，老师学生就能用到 |
| main | 正式版本的代码 |
| Issue #174 | 工程断点记录。哪怕换一个 AI，也能从这里接上进度 |
| 草稿 / 审核 / 发布 | AI 或老师先写草稿；老师审核通过后，才会到学生和家长那里 |
| 首答 | 学生对一道题的第一次作答。掌握度只算首答 |
| 开关 | 有些模块可以整体打开或关闭，比如知识地图、晚托作业助手。目前都已开启 |
| 旧 iPad / iOS 12 | 学生常用的旧设备。新页面要专门兼容它 |
| 人工合并 | 只改文档或受保护文件的 PR，需要人在 GitHub 页面上点合并 |

# 2. 数据设计稿(新增表,均带 school_id)

沿用 `classroom_sessions` 的 Table 注册方式,不改旧表字段,只加字段 `classroom_sessions.mode`(默认 "standard",周末课 "weekend")——或用新表关联,二选一待确认,倾向新表关联以零侵入。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `kp_cards` | school_id, grade, subject, knowledge_key, summary, steps_json, image_refs, common_mistakes, status(draft/approved), approved_by | 知识点讲解卡片;knowledge_key 对应 `questions.knowledge` |
| `lesson_stages` | lesson_id, stage_no(1-7), stage_type, planned_min, slides_json, question_ids | 每课 7 环节模板;slides_json 含页类型(文字/图/例题) |
| `question_hints` | school_id, question_ref(teaching/questions), level(1-3), text, status(draft/approved) | AI 预生成+老师审核 |
| `weekend_runs` | session_id, lesson_id, stage_no, started_at, ended_at, actual_min | 环节实际用时 |
| `hint_usage` | session_id, student_id, question_ref, max_level, correct, created_at | 提示用量,进步指标来源 |
| `peer_help` | session_id, tutor_id, tutee_id, question_ref, followup_correct, created_at | 强带弱闭环;可挂 presenter_turn_id |
| `class_metrics` | session_id, stage, completion_rate, created_at | 完成率走势(练习后/巩固后) |
| `progress_awards` | session_id, student_id, kind(progress/tutor/team), points, basis_json, ledger_id | 记账到 `point_ledger`,basis 保存口径输入以便复算 |
| `term_schedule` | program_id, lesson_no, school_week, school_unit, shifted | 学校进度对应与顺延 |
| `session_archive` | session_id, summary_json, parent_brief_json | 课堂档案与家长简报(只读生成) |

## 与现有数据对应
- 错题→卡片:`wrong_question_records.knowledge` = `kp_cards.knowledge_key`(沿用 `homework_knowledge.match_knowledge` 模糊匹配)。
- 薄弱点标记:读 `homework_ai_knowledge` 与 `knowledge_flags`,不重复存储。
- 事件:关键动作同时写 `classroom_events`,档案由事件+上表汇总。

## 保留策略
- 档案与积分长期保留;提示用量明细同 AI 辅助记录 90 天后可聚合保留。

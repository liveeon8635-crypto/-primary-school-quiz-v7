## 0. 范围

**MVP（现在做）**——只有四件事：
1. **作业清单导入**：教师粘贴文字或上传截图 → AI 解析为清单 → 教师确认后分配给学生。
2. **拍照识题**：学生拍题 → 识别 → 学生确认题目文字。
3. **AI 解题**：只给一种解法、逐步展开，固定显示「AI 可能出错，请自己判断」；按年级出解法；数学结果用程序核对。
4. **求助教师**：学生点求助 → 教师端列表显示题目和 AI 对话。

**安全底线**：只向模型发送**题目内容和年级**；照片识别后**立即删除**；**每个学生有调用上限**；学生端功能有开关，**默认关闭**。
**登录**：沿用现有方式（现有账号登录；#701 班级码登录若已启用也照常可用），本功能**不改任何登录/JWT/权限代码**。

**不做**：见 §12。

## 3. 功能 1：作业清单导入

### 3.1 流程
1. 教师在「晚托作业」页：粘贴通知文字，或上传通知截图（截图先走 §4 的视觉识别得到文字，**教师可编辑该文字**再解析）。
2. 点「解析」：服务端把通知**文字**发给文本模型，要求只输出 JSON：条目数组（学科、内容、页码、要求）和候选 `group_label`（学校+班级文字）。解析失败直接提示"请手动录入"，**不自动重试**（控成本）。
3. 教师在确认页逐条修改/增删，选择**学生**（从自己班的学生列表多选，可全选），点「发布」。
4. 发布后写入 `homework_recipients`；`raw_text` 清空；学生端出现"今日作业"清单，可逐项勾选。
- 教师确认是硬门槛：发布前学生看不到任何内容。
- 通知文字里的手机号、长数字串在发给模型前做正则脱敏；页面提示"文字将发送给 AI 服务商"。

### 3.2 API 草案（均受开关保护，关闭时 404）
教师：`POST /teacher/homework/parse`（text 或 image）、`PUT /teacher/homework/notices/{id}`、`POST /teacher/homework/notices/{id}/publish`、`GET /teacher/homework/notices`
学生：`GET /student/homework/today`、`POST /student/homework/items/{notice_id}/{idx}/done`

## 4. 功能 2：拍照识题

### 4.1 流程
```
学生点「拍题」→ 取景提示 → 拍照上传（单张）
 → [调用 A：视觉识别] 图片 → 题目文字（+是否含图、置信度）
 → 服务端立即丢弃图片（只在内存，不落盘、不入库、不写日志）
 → 学生看到文字，可修改 → 点「确认」才继续      ← 硬门槛
```
- 取景提示：「只拍这一道题，让题目占满画面；避开人脸、姓名、学号；光线要亮，别有阴影。」不支持整页多题。
- 识别失败/学生觉得不对：可重拍或**手输题目**（降级路径，不依赖视觉模型）。

### 4.2 视觉模块（可切换，新模块内独立实现）
- 接口：`recognize(image_bytes) -> {text, hasFigure, confidence}`；实现可换 DeepSeek / Qwen / 智谱。
- **不改原映射表**：`AI_DEEPSEEK_LEGACY_MODEL_ALIASES`（:3105）会把 `deepseek-v4-flash-vision-exp` 改成 `deepseek-flash`；视觉模块有自己的模型名解析，原映射与文本链路行为不变（测试断言）。
- 配置全部来自环境变量（用户在 Render 设置；**代码与仓库不出现 key**，日志/报错不回显）：`HOMEWORK_VISION_PROVIDER`、`HOMEWORK_VISION_BASE_URL`、`HOMEWORK_VISION_MODEL`、`HOMEWORK_VISION_API_KEY`；缺任一项则拍照入口关闭，只留手输。
- **P1 直接实测**：先试 `deepseek-v4-flash-vision-exp`（官方文档 api-docs.deepseek.com 从沙箱不可访问，模型名/图片入参格式/限制/价格仍【未确认】）。按 OpenAI 兼容 `image_url` + data-URI 试；结论写入 PR 描述；价格由用户核对控制台。
- 调用仍写 `AIUsageLog`（`feature=homework_vision`，只记耗时/token）；要求学校 `enabled` 且 `allow_student_data`。
- 照片处理硬规则：不用 `HomeworkMedia`；异常路径同样不落盘；日志不打印 base64/文件名；前端上传前缩放到限定边长（降低流量与内存）。

## 5. 功能 3：AI 解题

### 5.1 调用 B（与识别完全独立）
- 触发：学生确认题目文字后。入参**只有**：确认后的题目文字 + 年级（如「三年级」）。
- 提示词硬性要求：①只给**一种**解法；②只用该年级已学过的方法，不得超纲（如低年级不用设未知数）；③输出 JSON：`{method, steps:[{n,text}], answer, expression, knowledgePoint}`；④不要求也不接受任何身份信息。
- 展示：步骤逐条展开（点一步看一步），最后显示答案；页面**固定显示「AI 可能出错，请自己判断」**，不可关闭。
- 超时：识别 ≤20s、讲解 ≤30s；超时提示"稍后再试，或点求助老师"。

### 5.2 程序核对（sympy）
- 依赖：`requirements.txt` 当前**没有** sympy（已核实）；用户已同意新增，固定版本号，随 PR4 引入。
- 要求模型在 JSON 里给出 `expression`（算式）与 `answer`；服务端**不 `eval`/不直接 `sympify` 模型输出**，只经**白名单解析器**（数字、四则、括号、分数、幂、受限函数）后再求值；输入长度/复杂度设上限，求值设超时。纯四则/分数先用标准库 `fractions.Fraction`，方程与化简用 sympy。
- 能核对的：纯计算、简易方程、应用题的列式求值（只能验证"算对没有"，验证不了"列式对不对"）。不能核对的（带图、文字推理）→ `verify_status=skipped`，页面照常显示固定警示，并提示"可以点求助老师"。
- **不一致（mismatch）**：**不向学生展示该答案**；改为"这道题我没有把握，已请老师帮忙"，自动升级为求助（`escalate_reason=verify_mismatch`）。最多允许 1 次复核重试，仍不一致才升级。
- 核对通过也**不**对学生宣称"已验证正确"，避免虚假确定感。

## 6. 功能 4：求助教师

- 学生入口：每次解答下方有「求助老师」按钮，可写一句话（`student_note`）；校验不一致时自动升级；识别/解答失败也提供该按钮。
- 教师端「求助列表」（只含自己班学生）：按升级时间排序；每条显示学生（教师设备上显示 `users.name`）、题目文字、AI 的解法与核对结果、学生留言、等待时长；**没有原图**（已删除，教师需看学生纸面）。
- 教师操作：「已处理」并可写 `teacher_note`；状态 `escalated → resolved`。
- 刷新：页面轮询（5–10 秒，页面隐藏时暂停），沿用现有"只轮询、不用 WebSocket/SSE"的约束。
- 权限：教师只能看自己班学生的记录，其余 404；学生只能看自己的。

## 7. 安全底线与限流

### 7.1 发送给模型的字段（白名单，唯一的 prompt 构造函数，测试断言）
| 调用 | 发送 | 不发送 |
|---|---|---|
| 清单解析 | 通知**文字**（已脱敏手机号/长数字） | 学生/教师姓名、用户名、ID、机构名（来自系统的字段一律不拼进 prompt） |

### 7.2 调用上限
| 层级 | 草案值（环境变量可调；压测校准） |
|---|---|
| 每生每分钟 | ≤ 2 次求助 |
| 每生每日（`HOMEWORK_STUDENT_DAILY_LIMIT`，默认 8） | ≤ 8 次求助 / ≤ 24 次调用（按学校本地日；沿用现有本地时间工具，实现时核对【未确认】） |
| 学校·学生功能小时额度 | `HOMEWORK_SCHOOL_HOURLY_LIMIT`，默认 300（按晚托高峰约 30 人 × 3–5 次求助 × 2–3 次调用 ≈ 180–450 次/晚估算；【未确认】需压测） |
| 全校同时在途的 AI 请求 | ≤ 8（进程内信号量，单实例有效；【未确认】若将来多实例需改） |
| 超限 | 429 + 友好文案 + 引导"求助老师"，不静默失败 |

## 8. 识别测试方案（缩略）

- 样本 20–30 张：机构教师用**真实练习册**只拍题目区域，不出现姓名；**私有存放**，不进仓库/CI/PR，评测后删除。
- 类别：手写清晰、手写潦草、竖式、分数、几何含图、整页多题（观察项）、光线差、通知截图（含他人头像，需先遮挡）。
- 指标：**题意准确**（数字/运算符/单位/分数结构全部正确才算对）为核心；另记字符级准确率、学生改动 ≤2 处的可用率、耗时、失败率；多家视觉模型同图并行对比。
- 通过线：**用户审核后另行回复**，回复前不作为合入门槛。未达线 → 降级为"手输题目 + 文本解题"，识别作为增强。
- 评测脚本只读离线，放 `scripts/`，输出只写样本序号。

## 9. 成本估算

- 每次求助 = 识别 1 + 解题 1（+ 复核 0–1）；教师每份通知 = 解析 1（截图再加识别 1）。
- 成本 ≈ 次数 × (输入 token × 单价 + 输出 token × 单价)；题目文字短，解题输出约数百 token；图片按各家规则折算。
- 各家单价【未确认】（仓库无价格数据）；P1 实测时用 `AIUsageLog.input_tokens/output_tokens`（:461，`_ai_usage_values` 已解析）回填，再给出元/生/晚区间。

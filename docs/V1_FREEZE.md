# 长缨辅学 V1 冻结基线

## 冻结目标

V1 的目标不是一次性完成所有学校与机构数据模型，而是形成一套可以在当前线下教学中长期使用、可审阅、可继续演进的稳定工作台。冻结后，V1 第一层产品结构原则上不再因为“看起来更完整”而继续扩张；后续优先处理真实使用中发现的缺陷、安全问题和已经验证必要的数据能力。

## 当前 V1 基线

V1 以“一个学生 → 一份长期连续档案”为核心，已经形成以下稳定主路径：

1. 当前教学工作台；
2. 当前可见学生集合；
3. 学生连续发展档案；
4. 作业、成绩、薄弱知识与教学跟进；
5. 往期教学查询；
6. 升年级与升学衔接准备度；
7. 明确的原系统维护入口。

当前教师学生集合读取全部账号可见教学归属，按稳定 student_id 聚合，过滤已归档账号，并对同名不同 ID 保持审计而不是自动合并。详情页展示受保护接口已经返回的完整可见记录，不再使用演示阶段的前 4/6/8/10/12/30 条静默截断。

## 读取可靠性

移动端和教学现场可能出现弱网、单个班级读取失败或浏览器异常。V1 的冻结要求是：

- 单个教学归属读取失败不能拖垮整页；
- 部分读取失败必须明确提示，不能把失败伪装成“0 个学生”；
- 顶层学生列表或工作台读取失败必须显示为读取异常；
- 未预期的浏览器读取/渲染异常提供明确的重新加载入口；
- 失败提示不改变数据库，不新增写入路径，也不绕过权限。

## 事实边界

V1 只显示现有数据能够支持的事实：

- 学校模式在标准化课表模型建立前只显示真实教学事实概览，不虚构课节、教室或时间；
- “稳定掌握”不由一次成绩或平均分自动判定；
- 未标准化的学年、学期和教学周期字段不由界面伪造；
- 同名学生不会因为姓名一致而自动合并；
- 升学衔接目前读取现有档案事实并展示准备度，不自动修改年级、学校或教学归属。

## V1 发布验收路径

每次冻结版变更至少需要通过以下路径：

- `/` 能进入 V1；
- `/v1`、`/v1/workspace`、`/v1/student`、`/v1/history`、`/v1/transition` 均可加载；
- 移动端底部导航保留安全区；
- 当前学生数量、学生列表和学生详情使用一致的可见范围；
- 同一 student_id 的多个教学归属在一份档案中聚合；
- 归档学生不作为当前活动学生重复出现；
- 部分读取失败和顶层读取失败有可见提示；
- CI 全部通过后才允许进入生产合并；
- Render 自动部署后必须确认 live 与 `/health` 200。

## 冻结后进入 V1.1 / V2 的事项

以下能力不再继续塞进 V1 收口，而作为后续数据模型阶段独立推进：

- 同一真实用户的多身份持久化；
- 标准化学年、学期、教学周期与学校组织层级；
- 掌握阶段及跨时间保留、独立完成、迁移证据落表；
- 升学衔接计划的独立保存与分析；
- 标准化学校课表、课节、备课、测验和教学评价数据域；
- 标准化历史教学的学年/学期筛选 API；
- 作业完成主体等提交行为字段持久化。

这些事项涉及生产数据库结构或新的业务写入时，必须先有迁移方案、回滚边界和单独的生产授权。

## 冻结规则

V1 冻结后，允许继续进入 V1 的变更主要包括：

- 明确 bug 修复；
- 安全、权限和数据一致性修复；
- 手机端性能和可靠性修复；
- 不改变产品第一层结构的可用性改进；
- 真实教学使用证明必要的小范围调整。

新增第一层业务概念、生产表、批量数据修改或新的自动判断规则，默认进入 V1.1 / V2 评审，不作为 V1 “继续收口”的理由。

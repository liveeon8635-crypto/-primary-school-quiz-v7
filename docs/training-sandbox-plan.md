# 长缨角色实操沙盒实施方案

## 目标

把当前说明式“新手教学”升级为可反复练习的真实操作训练环境。用户以当前登录身份为主身份，在与正式业务隔离的临时沙盒中使用长缨真实页面形态和真实业务顺序完成操作；需要关联角色时，可在“切换关联虚拟账号亲自体验”和“自动模拟关联角色数据后继续”之间选择。

训练必须同时解决两类问题：

1. **操作理解**：用户知道每个功能页面在哪里、怎样操作、上下游是什么。
2. **角色沟通**：教师、学生、家长、管理员理解同一业务事实在不同角色端分别如何出现，减少“老师说已布置、学生不知道去哪看”这类沟通断层。

## 设计原则

- 主身份连续：训练过程中始终保留当前登录身份作为主身份。
- 跨角色可选：需要关联角色时，用户可选择切换虚拟账号或自动模拟。
- 真操作、假业务数据：前端按真实页面和真实流程操作，训练数据不进入正式数据库、统计、积分、学习证据、商业计量或正式审计。
- 页面关系可解释：每一步都明确“谁操作、产生什么、谁能看到、另一角色看到什么、下一步由谁接手”。
- 任意复习：支持上一步、跳过、重做本步、从指定场景开始、重置整条训练。
- 结果一致：手动切换虚拟学生与自动模拟必须产生同结构的训练结果，保证后续教师流程一致。
- 不替用户做决定：AI/模拟用于形成训练条件，不替教师执行真实发布、评分确认或课堂推进。

## 角色主线

### 教师

产品主线 → 建班 → 加学生 → 连续档案 → 组卷/AI出题 → 审核 → 布置 → 学生作答 → 证据回流 → 针对练习 → 全班复盘 → 互动课堂/随堂检测 → 积分与评价 → 往期教学 → 升年级衔接 → 全部功能关系图。

### 学生

课堂 → 作业 → 逐题作答 → 提交 → 结果 → 错题 → 针对练习 → 学情 → 积分 → 历史/账号。

### 家长

孩子课程 → 作业状态 → 学情 → 课堂表现/积分 → 连续档案与历史 → 账号与关联关系。

### 管理员

平台总览 → 账号 → 班级/教学归属 → 权限边界 → 积分规则 → 审计 → 系统设置 → 历史连续性。

## 关联角色体验

每个跨角色节点提供两种路径：

- **亲自体验**：临时切换到关联虚拟角色，不重新登录；顶部持续显示“主身份 / 当前体验身份”；完成后一键返回主身份原位置。
- **自动模拟**：保持当前主身份，由训练沙盒自动生成必要的关联角色动作和结果，并明确标注“模拟数据，不进入正式档案”。

桌面端后续可增加教师/学生双视角并排预览；iPhone 优先采用快速角色切换。

## 场景起点

- 从零开始
- 从已布置作业开始
- 从已有学生提交开始
- 从课堂复盘开始

场景预置通过同一套沙盒动作构建，不另造一套假数据逻辑。

## 页面训练框架

训练主体必须是产品页面，不再以“大步骤卡片”占据主屏。

建议固定一条轻量训练栏：

> 实操沙盒｜钟老师·教师｜第 7/16 关：布置作业

并提供：

- 上一步
- 跳过
- 查看角色关系
- 重做本步
- 下一步
- 退出并保存训练进度
- 重置沙盒

产品助手只负责解释当前页面、下一步和反馈，不覆盖主操作区。

## 每一步的教学信息

统一使用以下字段：

- 当前身份
- 当前页面
- 本步目标
- 完成条件
- 产生的数据
- 谁能看到
- 其他角色会看到什么
- 最常见沟通误区
- 上游来源
- 下游去向
- 是否需要关联角色
- 关联角色体验方式

## 数据边界

训练数据不得进入：

- 正式 classes / users / papers / assignments / submissions
- 正式积分账本
- LearningEvidenceEvent 或掌握状态
- 正式课堂记录、讲义发布、衔接计划
- 正式业务统计与排行榜
- 商业计量、收费、订单或支付
- 正式审计日志

训练会话需：

- 按 authenticated owner 隔离
- 有 TTL 自动过期
- 有最大会话数上限
- 可手动重置
- 只保存训练进度/偏好时，不保存临时业务事实

## 分阶段实施

### P0：安全基础

- 临时训练会话
- 主身份/当前体验身份
- 角色流程和页面关系图
- 关联角色 switch / simulate
- 场景预置
- 重置
- owner 隔离
- 无正式数据库写入

### P1：教师真实操作界面

把教师主线接入真实页面形态：

- 班级
- 学生
- 试卷/AI出题
- 审核
- 作业
- 学生视角/模拟提交
- 证据回流
- 针对练习

旧的说明式 16 步降级为可折叠路线图。

### P2：课堂与长期链路

- 全班数据
- 复盘讲义
- 互动课堂
- 随堂检测
- 积分
- 历史
- 升年级衔接

### P3：其他身份

- 学生完整训练
- 家长完整训练
- 管理员完整训练
- 跨角色沟通场景
- 桌面双视角

### P4：反馈与持续优化

- 每一步卡点/跳过原因
- 产品助手上下文
- 反馈进入 Freeman 项目反馈池
- 只记录训练体验元数据，不记录敏感业务内容

## 验收标准

1. 登录并选身份后能启动对应实操沙盒。
2. 教师能从零完成完整教学闭环。
3. 跨角色节点可自由选择 switch 或 simulate。
4. 两种路径产生相同结构的后续训练数据。
5. 切虚拟账号不要求重新登录。
6. 训练页面与正式页面保持相同信息架构和主要交互。
7. 每一步都能解释其他角色看到什么以及下一步由谁操作。
8. 任一步可跳过、回退、重做和复习。
9. 支持场景起点与整条沙盒重置。
10. 训练数据不进入任何正式业务表、学习证据、积分、统计或商业计量。
11. iPhone 不出现浮层遮挡、无法滚动、点击失效或“卡死”。
12. 完成训练后用户能从“全部功能关系图”理解每个页面的上游、下游和角色关系。
